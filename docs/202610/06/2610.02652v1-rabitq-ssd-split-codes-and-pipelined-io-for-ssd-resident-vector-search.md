## 摘要
当向量集合超出DRAM容量时，SSD驻留的近似最近邻搜索至关重要。挑战在于减少SSD读取，并通过并发读取以及与计算重叠来隐藏I/O延迟。然而，对于基于图的搜索，渐进式候选发现限制了提前进行I/O规划；而IVF搜索会完整读取倒排列表，导致不必要的SSD读取。本文提出RaBitQ-SSD，这是IVF-RaBitQ面向SSD驻留向量搜索的扩展。具体而言，我们提出Split-RaBitQ，它在DRAM中保留每个二进制编码的可配置前缀，使得内存中编码存储低于每维一位。利用这种部分表示，它提供具有概率误差界的无偏距离估计器。一旦内存中的粗量化器识别出候选列表，该误差界便可支持在列表内对单个候选进行剪枝，从而实现更细粒度的SSD访问。我们还设计了一种异步搜索流水线，将候选剪枝与SSD读取调度相协调，以减少不必要的读取，同时将I/O与计算重叠。在从500万到10亿向量的数据集上，RaBitQ-SSD在90%召回率下吞吐量最高达到基于图的基线的1.74倍，同时将SSD页面读取减少最多3.8倍。其SSD上的索引比DiskANN小最多7.0倍，构建速度快最多10.0倍。我们还在一台配备单个SSD的单机上构建并搜索了100亿向量的索引，在90%召回率下达到每秒超过3,000次查询。

## Abstract
SSD-resident approximate nearest-neighbor search is essential when vector collections exceed DRAM capacity. The challenge is to reduce SSD reads and hide I/O latency through concurrent reads and overlap with computation. However, for graph-based search, progressive candidate discovery limits advance I/O planning while IVF search reads inverted lists in full, incurring unnecessary SSD reads. In this paper, we present RaBitQ-SSD, an extension of IVF-RaBitQ for SSD-resident vector search. Specifically, we propose Split-RaBitQ, which retains a configurable prefix of each binary code in DRAM, allowing in-memory code storage below one bit per dimension. Using this partial representation, it provides an unbiased distance estimator with a probabilistic error bound. Once the in-memory coarse quantizer identifies candidate lists, this bound supports pruning individual candidates within them, enabling finer-grained SSD access. We also design an asynchronous search pipeline that coordinates candidate pruning with SSD read scheduling to reduce unnecessary reads while overlapping I/O with computation. On datasets ranging from $5$ million to $1$ billion vectors, RaBitQ-SSD delivers up to $1.74\times$ the throughput of graph-based baselines at $90\%$ recall, while reducing SSD page reads by up to $3.8\times$. Its on-SSD indexes are up to $7.0\times$ smaller and $10.0\times$ faster to build than DiskANN. We also build and search an index of $10$ billion vectors on a single machine with one SSD, achieving over $3{,}000$ queries per second at $90\%$ recall.

## 1. 核心问题与整体含义

- **背景**：现代嵌入模型产生高维向量，向量集合常超过单机 DRAM 容量。例如 10 亿条 1024 维 FP32 向量约占 4 TB。SSD 每字节成本远低于 DRAM，且单块 PCIe 4.0 NVMe SSD 可提供百万级随机读 IOPS，因此“向量/高精度表示放 SSD、压缩码放内存”成为十亿级 ANN 搜索的重要路线。
- **核心挑战**：SSD 驻留 ANN 搜索必须同时做到两点：减少 SSD 读取量；通过并发读取和 I/O-计算重叠隐藏 SSD 延迟。
- **现有方法局限**：
  - **图方法**（DiskANN、Starling、PipeANN 等）：候选点是渐进发现的，扩展未缓存节点前必须读取其磁盘记录以获得邻居，因此难以提前规划 I/O；同步 beam search 每轮等待 I/O，限制重叠；PipeANN 虽可推测性发读，但后续 I/O 完成可能暴露更好候选，造成浪费。
  - **IVF 方法**（SPANN、HELMSMAN 等）：内存粗量化器先选出候选倒排列表，但通常整表读取倒排列表，无法在列表内做细粒度剪枝，产生不必要 SSD 读。
- **论文整体含义**：RaBitQ-SSD 将内存版 IVF-RaBitQ 扩展到 SSD 驻留场景，通过 **Split-RaBitQ** 在内存只保留二进制码前缀，实现低于 1 bit/维的内存编码，并用概率误差界对倒排列表内单个候选剪枝；再配合异步流水线调度 SSD 读取，从而减少页读取并重叠 I/O 与计算。

## 2. 方法论：核心思想、关键技术细节与流程

- **核心思想**：把 RaBitQ 二进制码拆成内存前缀和 SSD 后缀。内存前缀用于粗筛和剪枝，SSD 保存后缀、ex-code 及重排因子用于精确重排。内存占用由前缀长度 \(D_m\) 可配置，支持低于 1 bit/维。
- **Split-RaBitQ 设计**：
  - 内存保留每个向量二进制码前 \(D_m\) 位前缀，以及三个用于计算下界的因子；前缀按 32 个一组打包以支持 FastScan。
  - SSD 保存剩余 \(D_s = D - D_m\) 位、ex-code 和两个重排因子。
  - 距离估计：  
    \[
    \hat{\beta}_{D_m} = \frac{D}{D_m}\cdot \frac{\langle \bar{o}_{D_m}, q\rangle}{\langle \bar{o}, o\rangle}
    \]
    其中 \(\langle \bar{o}, o\rangle\) 在索引期预计算，\(\langle \bar{o}_{D_m}, q\rangle\) 是前缀坐标上的内积。该估计器对 \(\langle o,q\rangle\) 无偏。
  - 误差界：论文证明在 \(0<\epsilon\le \sqrt{D_m}/3\) 时，
    \[
    \Pr\left(|\hat{\beta}_{D_m}-\langle o,q\rangle|>\frac{\epsilon}{\sqrt{D_m}}\right)\le 2e^{-c_1\epsilon^2}
    \]
    即估计误差约为 \(O(1/\sqrt{D_m})\)。该界可转化为距离下界 \(LB_{D_m}\)，用于剪枝。
- **搜索流水线**：
  - **粗量化**：内存中的 IRQ（in-memory IVF-RaBitQ over centroids）返回 \(n_{\text{probe}}\) 个最近簇，按簇距离由近到远扫描。
  - **批扫描**：对每个簇按 32 个向量一批做 FastScan，用前缀码和因子计算每个点的下界。若 \(LB_{D_m} < \text{dist}_k\)，该点存活。
  - **页候选合并**：同一 SSD 页内存活点合并为 page candidate，页下界为其成员最小下界。
  - **优先级集合**：页候选按页下界排序，异步提交读请求，保持每查询最多 \(Q\) 个 in-flight 读。
  - **发读前重筛**：提交前用当前 \(\text{dist}_k\) 再检查，若页下界已不低于阈值则丢弃，避免无效读。
  - **收割**：读取完成后，对页内成员再次用当前 \(\text{dist}_k\) 筛选，存活者重排并更新 KNNSet。
  - **Drain 与 \(\alpha\)-quantile 阈值**：扫描结束后处理未完成 I/O。为避免 drain 过长，仅当待读页下界低于当前 KNNSet 的 \(\alpha k\) 分位阈值时才发读，默认 \(\alpha=0.4\)。该策略牺牲部分尾部确定性，但保证至少 \(\alpha\) 比例真 top-\(\alpha k\) 不被剪枝。
- **流水线演进**：Naive（逐候选阻塞读）→ Coalesced（同页合并读）→ Overlapped（异步读、不阻塞，但易浪费）→ Scheduled（优先级集合 + 有界 in-flight + 发读前重筛）→ Full（再加 \(\alpha\)-quantile drain 阈值）。
