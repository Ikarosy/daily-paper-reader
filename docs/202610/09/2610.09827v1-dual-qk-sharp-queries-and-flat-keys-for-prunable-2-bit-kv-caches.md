## 摘要
长输入和扩展生成会增加键值（KV）缓存的存储与访问成本。低位量化可减少存储和内存流量，而查询通道剪枝可以进一步减少键缓存读取。基于旋转的量化会将键离群值的能量重新分布到各通道。为了保持计算不变性，必须对查询应用相同的正交变换，从而保持查询-键点积。然而，这种旋转会分散查询能量，削弱需保留的少数大分量与需剪枝的众多小分量之间的分离度。我们提出 Dual-QK，它使用成对的非正交查询与键变换来解决这一冲突。利用校准后的查询和键统计量，Dual-QK 将部分键白化与查询对齐基相结合，以平衡 INT2 量化的键尺度，并集中查询能量以进行动态通道剪枝。通道 0 保护和桶相对 RoPE 支持长上下文中的低位精度。在四个模型、五个生成基准和长上下文检索任务上的实验表明，在 40% 查询通道稀疏度下，Dual-QK 在大多数任务上相比 OSCAR 提高了准确率。在 128K 上下文下，Dual-QK 相对于未剪枝的 BF16 提供 $6.8\times$ 的 KV 缓存压缩，并估计将 KV 读取量减少 $8.3\times$。在所评估的配置下，我们的 SGLang 实现最高达到未剪枝 BF16 解码吞吐量的 $3.75\times$。

## Abstract
Long inputs and extended generation increase the storage and access costs of the key-value (KV) cache. Low-bit quantization reduces storage and memory traffic, while query-channel pruning can further reduce key-cache reads. Rotation-based quantization redistributes the energy of key outliers across channels. To maintain computational invariance, the same orthogonal transform must be applied to queries, preserving query-key dot products. However, this rotation can disperse query energy, weakening the separation between a few large components to retain and many small ones to prune. We introduce Dual-QK, which uses paired non-orthogonal query and key transforms to address this conflict. Using calibrated query and key statistics, Dual-QK combines partial key whitening with a query-aligned basis to balance key scales for INT2 quantization and concentrate query energy for dynamic channel pruning. Channel-0 protection and bucket-relative RoPE support low-bit accuracy over long contexts. Experiments on four models across five generative benchmarks and long-context retrieval tasks show improved accuracy over OSCAR on most tasks at 40% query-channel sparsity. At a 128K context, Dual-QK provides $6.8\times$ KV-cache compression and an estimated $8.3\times$ reduction in KV read volume relative to unpruned BF16. Under the evaluated configurations, our SGLang implementation achieves up to $3.75\times$ the decoding throughput of unpruned BF16.

# Dual-QK 论文中文总结

## 1. 核心问题与整体含义

- **研究背景**：长上下文与长生成使 Transformer 的 KV 缓存存储和读取成本急剧上升。低比特量化可降低每元素位数，查询通道剪枝可进一步减少键缓存读取量。
- **核心冲突**：
  - 键量化偏好“平坦分布”，避免离群通道扩大量化范围、降低有效分辨率。
  - 查询通道剪枝偏好“锐利分布”，即少数通道集中大部分查询能量，便于按当前查询动态保留重要通道。
- **现有方法矛盾**：
  - 旋转类量化（如 Hadamard、OSCAR）通过正交变换分散键离群值，但为保持 QK 点积不变，同一变换也作用于查询，可能分散查询能量，削弱剪枝效果。
  - Q-PCA 可集中查询能量，但不能显式控制键离群值，不利于 INT2 键量化。
- **整体含义**：论文提出 Dual-QK，用成对非正交查询/键变换，同时构造“平坦键”和“锐利查询”，在保持压缩前 QK 点积不变的前提下，联合支持 INT2 KV 量化与动态查询通道剪枝，面向长上下文推理的高压缩、低读取和高吞吐场景。

## 2. 方法论

- **核心思想**：对任意可逆矩阵 \(A\)，令键变换为 \(B=A^{-T}\)，则
  \[
  (QA)(KB)^T=QK^T
  \]
  即查询和键可使用不同、非正交的变换，只要成对匹配，就能在量化与剪枝前保持原始注意力分数。这扩展了以往共享正交旋转的做法。
- **统计校准**：
  - 对每层、每 KV head 估计 RoPE 后查询和键的非中心二阶矩 \(C_Q=\mathbb{E}[q^Tq]\)、\(C_K=\mathbb{E}[k^Tk]\)。
  - 查询统计在共享同一 KV head 的 GQA 查询头之间池化。
- **部分键白化**：
  - 设 \(G=C_K+\epsilon I\)，键乘以 \(G^{-\alpha/2}\)，查询乘以 \(G^{\alpha/2}\)，其中 \(\alpha\in[0,1]\) 控制白化强度。
  - 目标是在不强制查询同尺度变化的情况下，压缩键方向上的尺度差异，使键分布更平坦。
- **查询对齐基**：
  - 对补偿后的查询矩做特征分解：
    \[
    G^{\alpha/2}C_QG^{\alpha/2}=U\Lambda U^T
    \]
  - 取
    \[
    A_0=G^{\alpha/2}U,\quad B_0=G^{-\alpha/2}U
    \]
  - 变换后查询矩为 \(\Lambda\)，前几个通道集中主要查询能量。
  - \(\alpha=0\) 退化为 Q-PCA；\(\alpha=1\) 对正则化键矩做白化。论文按模型选择一次 \(\alpha\)，离线计算并复用。
- **对角细化**：
  - 进一步引入正对角矩阵 \(D\)，令 \(A=A_0D\)，\(B=B_0D^{-1}\)。
  - \(D\) 通过校准减少键量化引起的注意力分数误差，并固定通道 0 的缩放为 1。缩放在同一通道的 Q/K 间抵消，因此保持点积和固定通道集合贡献不变。
- **动态查询通道剪枝**：
  - 在 GQA 中，一个 KV head 对应 \(g\) 个查询头。对每个通道 \(j\)，计算组内 L2 范数：
    \[
    e_j=\sqrt{\sum_{h=1}^g(q'_{h,j})^2}
    \]
  - 保留 \(e_j\) 最大的 \(m\) 个通道，并对组内所有查询头使用同一 mask。该规则在固定通道预算下最大化保留查询能量。
  - 所有键通道仍存储，未选通道可被后续查询使用；掩码在 base 坐标中计算，不受对角细化影响。
- **INT2 KV 量化**：
  - 通道 0 通常对应最大查询能量，对量化误差敏感，因此保留为 BF16，并从其余通道的 INT2 范围估计中排除。
  - 其余通道每 token、每 KV head 使用非对称 INT2 网格。
  - 键以 channel-major 存储，每 128-token page 内每通道占连续 32 字节行；解码时仅异步拷贝被共享查询 mask 选中的行。
  - 值量化沿用 OSCAR 的校准旋转、裁剪和 INT2 配方；前 64 个和最近 256 个 token 的 K/V 保留 BF16。
- **桶相对 RoPE**：
  - 将位置划分为宽度 \(w=2048\) 的桶，桶 \(b\) 的锚点为 \(a_b=bw\)。
  - 用 \(T_b\) 撤销锚点处 RoPE，存储键和当前查询表示为：
    \[
    z_n=k_nT_bB,\quad \tilde q_b=qT_bA
    \]
  - 由于 \(T_b\) 正交且双变换抵消，未压缩点积不变：
    \[
    \tilde q_bz_n^T=qk_n^T
    \]
  - 该调整在双变换之前进行，因为一般通道变换不与 RoPE 交换。它使存储键的位置偏移限制在校准窗口内，但查询相对旧桶的偏移仍可能超出窗口。
