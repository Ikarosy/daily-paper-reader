## 摘要
在基于暂存器（scratchpad）的张量加速器（STA）上，混合专家（MoE）解码主要受限于专家权重的搬运，而计算引擎却处于空闲状态。这种数据流量难以隐藏，因为只有在路由之后才能确定专家；同时也难以在不损失质量或不增加关键路径工作的情况下加以缩减。我们提出 CARDAN，它将每个专家权重矩阵表示为向量量化分量与共享基低秩分量之和，并将该表示与多引擎解码数据流进行协同设计。该表示将专家共有的工作与专家私有的工作分离开来，从而使数据流能够在多个引擎上让 DMA 与计算重叠。在 AWS Trainium3 上的五个 MoE 系列中，CARDAN 在所有五个模型上均达到或优于 BF16 教师模型的困惑度，并且相对于 AWS 的稠密 MoE 大内核，将批大小为 1 的解码速度提升 1.15–1.31 倍，在批大小为 16 时提升至 1.7 倍。

## Abstract
Mixture-of-Experts (MoE) decoding on scratchpad-based tensor accelerators (STA) is dominated by moving expert weights while the compute engines sit idle. This traffic is hard to hide, because the experts are known only after routing, and hard to shrink without losing quality or adding critical-path work. We present CARDAN, which represents each expert-weight matrix as a vector-quantized component plus a shared-basis low-rank component and co-designs this representation with a multi-engine decoding dataflow. The representation separates expert-common from expert-private work, so the dataflow overlaps DMA with computation on several engines. Across five MoE families on AWS Trainium3, CARDAN matches or improves BF16-teacher perplexity across all five models and speeds up batch-one decoding by 1.15-1.31x over AWS dense MoE megakernels, rising to 1.7x at batch size 16.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：MoE 通过稀疏激活专家在保持每 token FLOPs 近似不变的前提下扩大参数容量，已成为前沿模型主流架构。基于暂存器（Scratchpad / SPM）的张量加速器（STA，如 AWS Trainium、Google TPU、Intel Gaudi、华为 Ascend）用软件显式管理片上 SRAM，并用 DMA 在 HBM 与 SPM 间搬运张量，消除了 cache tag 开销与不可预测替换，能效与吞吐更高。
- **核心痛点**：在 STA 上，MoE **解码阶段**的延迟被专家权重搬运主导，而计算引擎大量闲置。以 Qwen3-30B-A3B（48 层，每层 128 专家中激活 8 个）为例，每层每 token 产生 75 MB（BF16）权重流量；实测专家权重加载占端到端延迟 **56%**，其中 **36.8%** 暴露在关键路径上；Gemma 4 与 Nemotron 3 分别为 **42.5%** 与 **30.5%**。同时 SIMD 引擎仅活跃 4.1%–4.7%，向量引擎仅 7%–10.1%。
- **两大挑战**：
  - **流量难隐藏**：专家集合只有路由之后才确定，预取窗口极短；已有基于历史激活的预取方案在 STA 上失效，因为预取会在有限 SPM 中制造长生命周期缓冲，并破坏编译器优化的数据局部性，甚至被编译器回收覆盖。
  - **流量难压缩**：稀疏张量格式会破坏 DMA 效率（DMA 服务时间不仅取决于字节数，还取决于包数量、地址规则性与串行化）；VQ 虽减少流量，但每个专家需存索引图，码字查找引入运行时开销，实测可占端到端解码延迟的 **20%**。
  - **引擎利用不足**：路由→搬运→计算构成严格依赖链，缺少并发空间；把 up/down 投影切细映射到不同引擎也因跨引擎操作数依赖与额外 SPM 流量而无法降延迟。
- **核心洞见**：为 STA **定制专家权重表示**，并将其与执行数据流**协同设计**，是同时解决数据搬运与硬件利用率不足的关键。

## 2. 方法论

### 2.1 混合专家权重表示（Hybrid VQ + LR）

- 将 gate/up 投影的专家权重矩阵表示为 **VQ 分量 + 共享基低秩分量之和**：
  - `o_e = W_e^T h ≈ Ŵ_e^T h = Q_B(J_e)^T h + C_e^T (D^T h)`
  - 其中 `Q_B(J_e)` 是由码本查表得到的 VQ 矩阵，`D` 为层内共享的低秩基张量，`C_e` 为专家私有系数。
- **共享 vs 私有划分**：层内共享 **权重码本 B** 与 **LR 基 D**（每 token 只加载一次）；每个激活专家只额外加载私有的 **索引图 J_e** 与 **系数 C_e**。gate 与 up 投影各自拥有独立码本。
- **为何必须混合**（互补性）：
  - 纯 LR 质量损失严重（Qwen3 PPL 从 9.82 恶化到 34.91，+255%），因为私有系数只能做低秩逼近，丢失专家特有信息。
  - 在约 4 bits/weight 时 NMSE：LR-only 13.46%、VQ+LR 5.72%、VQ-only 1.62%（d=2）。LR-only 在 8 bits 时（6.98%）仍不如 VQ+LR 在 3 bits 时（6.73%）。
  - 纯 VQ 精度更高但需缩小 d，而 d 每减半，索引选择次数翻倍，使 GpSimd 的索引选择成为关键路径瓶颈。
- **引擎互补性**：LR 为稠密矩阵–向量乘（张量引擎），VQ 为索引选择（GpSimd），二者互不依赖、可并行；随后标量引擎做专家激活 φ，向量引擎做 gate×up 逐元素乘。
- **只作用于 gate/up，down 保持 BF16**：因为所有激活专家共享同一 h，可复用 B/D 相关工作；down 接收的是专家私有中间激活 p_e，复用性差；且 down 权重 DMA 有 80% 以上能被 gate/up 计算重叠。

### 2.2 混合表示的初始化

- **免训练逐层初始化**：用标准乘积量化初始化 B 与 J_e；在代表性解码激活上以闭式解拟合 LR（一层一个共享 D，每专家一个 C_e），优先拟合影响专家输出的误差（含白化协方差 Σ_x 的加权闭式解，附录 A.1 给出 Ky Fan/Eckart–Young 最优性证明）。
- **端到端知识蒸馏**：损失为 `L = τ² D_KL(p_tea^Ω ‖ p_stu^Ω) + λ L_CE`，Ω 为教师 top-256 logits 的词表索引；仅更新 **B、D、C_e**，J_e 与其余参数全部冻结（"外科手术式专家替换"）。

### 2.3 多引擎解码数据流

- **打破路由–搬运–计算依赖链**，分成"路由无关的共享工作"与"路由相关的专家私有工作"，暴露三个重叠窗口：
  1. B、D 的 DMA 与路由器计算 top-k 重叠；
  2. 路由后张量引擎计算共享投影（`z = D^T h` 与投影码本 `T[b,k] = h_b^T B_k`），同时 DMA 加载 J_e、C_e；
  3. GpSimd 做索引选择、张量引擎算 `C_e^T z` 时，down 权重 DMA（地址在路由后即已知）并行发起。
- **消除冗余的三项技术**：
  - **共享投影复用**：共享投影每 token 只算一次而非每专家一次；投影码本 T 体积很小（K=256、H=2048 时 d=4 为 0.5 MiB，d=8 为 0.25 MiB），常驻 SBUF。
  - **跨专家 gather 批处理**：把激活专家的 J_e 拼接后一次性送入 `nc_n_gather`，把常数级 setup 成本从"每专家一次"降为"每批一次"；索引以 uint8 存储（对应 K=256），限制私有 HBM 流量。
  - **LR 与 VQ 的联合累加**：把码字选择的和与 LR 的 `C_e^T z` 累加到**同一 PSUM tile**，避免二者各自写回 SBUF 再读加写。
- **down 投影调度**：两个独立维度（权重/激活 stationary；累加在 SBUF 还是 PSUM）共 4 种候选，通过**离线 profiling** 决定——形状与布局在模型确定后跨 token/专家不变，故离线结果可在线复用。例如 OLMoE、Nemotron 选激活 stationary；Qwen3、DeepSeek-V2-Lite、Gemma-4 选权重 stationary。
