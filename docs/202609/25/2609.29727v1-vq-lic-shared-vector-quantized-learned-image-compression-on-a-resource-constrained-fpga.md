## 摘要
学习图像压缩（LIC）难以部署在资源极度受限的FPGA上，因为其实际运行速度不仅取决于算术运算量，还取决于内存流量、不同操作之间的不均衡，以及硬件如何对其工作进行批处理。我们提出VQ-LIC，一种非对称边云编解码器，其中紧凑的INT8深度可分离（DW）-逐点（PW）分析变换和多码本矢量量化（VQ）在边缘端运行于一对可复用的DW/PW引擎上，而重建则由更大的云端解码器处理。由于VQ码字匹配可以表示为点积，因此它被直接映射到同一个PW引擎上，从而无需单独的VQ计算阵列；据我们所知，这在FPGA LIC中尚属首次。一种新颖的延迟模型，基于FPGA的读取、DW、PW和写入开销的确定性RTL周期计数推导而来，可预测分析变换的逐块延迟；由于VQ共享相同的PW数据通路，该模型也适用于VQ。该模型直接在实际芯片上验证，对部署后的分析变换和VQ延迟的预测误差分别在0.26%和0.05%以内，并指导了三分块16-48-64变换的选择。训练后码本缩减则将VQ算术量和码本存储量降至原来的1/4，并缩小了固定宽度的潜在表示。在220个DSP的Zynq-7020上，VQ-LIC的中码率预设在CLIC 2017上以28.69 dB PSNR和13.06 dB MS-SSIM达到0.1398比特/像素，优于规模相近的神经编码器，并达到与规模大三个数量级的编解码器相当的率失真范围。完整的0.1945-kMAC/像素分析-VQ流水线在实际芯片上以47.98帧/秒和每帧42.84 mJ运行，与同类FPGA LIC加速器相比使用的DSP少一个数量级，同时在适度的PSNR折衷下实现了更低的比特率、更高的吞吐量和更低的每帧能耗。

## Abstract
Learned image compression (LIC) is hard to deploy on severely resource-constrained FPGAs, since how fast it actually runs depends not just on arithmetic count, but also on memory traffic, imbalance between different operations, and how the hardware batches its work. We present VQ-LIC, an asymmetric edge-cloud codec in which a compact INT8 depthwise (DW)-pointwise (PW) analysis transform and multi-codebook vector quantization (VQ) run at the edge on a reusable DW/PW engine pair, while reconstruction is handled by a larger cloud decoder. Since VQ codeword matching is expressible as a dot product, it is mapped directly onto the same PW engine, removing the need for a separate VQ compute array, to our knowledge a first for FPGA LIC. A novel latency model, derived from deterministic RTL cycle counts of an FPGA's read, DW, PW, and write costs, predicts an analysis transform's per-block latency; since VQ shares the same PW datapath, the model applies to VQ as well. Validated directly against silicon, the model predicts deployed analysis and VQ latency within 0.26\% and 0.05\%, and guides the selection of a three-block $16$-$48$-$64$ transform. Post-training codebook reduction then cuts VQ arithmetic and codebook storage by $4\times$ and shrinks the fixed-width latent representation. On a 220-DSP Zynq-7020, VQ-LIC's mid-rate preset reaches 0.1398 bits per pixel at 28.69 dB PSNR and 13.06 dB MS-SSIM on CLIC~2017, outperforming a similarly sized neural encoder and reaching a rate-distortion range comparable to a codec three orders of magnitude larger. The complete 0.1945-kMAC/pixel analysis-VQ pipeline runs at 47.98 frames per second and 42.84 mJ per frame on silicon, using an order of magnitude fewer DSPs than comparable FPGA LIC accelerators while achieving lower bitrate, higher throughput, and lower energy per frame at a modest PSNR tradeoff.

## 二、方法论

### 2.1 整体架构与设计范式

- **非对称边缘–云编解码**：边缘 PL（可编程逻辑）执行分析变换 + VQ；PS（Cortex-A9）执行表驱动 rANS 熵编码；云端约 651 万参数的 Transformer 解码器负责重建，位于 Zynq-7020 硬件边界之外。
- **分阶段算法–架构协同设计**（而非单体联合搜索）：
  1. 用延迟模型确定并验证加速器配置；
  2. 复用同一模型作为"延迟预言机"做编码器拓扑搜索；
  3. 因码字打分共享同一 PW 数据通路，再次复用该模型指导训练后码本基数精简。
- **规避边缘端熵模型推理**：不使用学习式超先验/自回归模型，改用**预共享条件概率表的 rANS**，把输入相关的熵模型推断从边缘路径移除。

### 2.2 分析变换（Encoder）

- 输入 1280×720，经 **3 个 stride-2 的 DW/PW 块**得到连续潜在 $z_e \in \mathbb{R}^{90\times160\times64}$，通道调度 $C^\star = (16, 48, 64)$。
- 每块：3×3 深度卷积（逐通道）+ 1×1 逐点卷积（跨通道）；BN 折叠进前一层卷积。
- 共 **4,491 个卷积权重**，**194.5 MAC/像素**；中间激活重量化为 INT8，最终 64 通道潜在量以无符号 INT8 存储，避免量化前额外转换。

### 2.3 硬件感知的乘积码本矢量量化

- **多码本 VQ**：维度 $D=64$ 的潜在向量被切分为 $M=4$ 个不相交子向量，每维 $D_m = 16$，各自在 $K$ 项子码本中匹配最近码字。
- **熵约束 VQ（ECVQ）**：不只选最近码字，还向"更易熵编码"的码字偏置：
  $$k_{u,v,m} = \arg\min_j \left[ \|z^{(m)}_{e,u,v} - e^{(m)}_j\|_2^2 - \beta_{\text{rate}} \log_2 p^{(m)}_j \right]$$
  其中 $p^{(m)}_j$ 为 EMA 估计的码字使用概率，$\beta_{\text{rate}}$ 控制码率压力。
- **整数部署形式**（关键工程细节）：展开上式并丢弃对所有候选码字共有的查询范数项，得到
  $$k^\star_{u,v,m} = \arg\min_j \left[ \|\tilde e^{(m)}_j - z_0\|_2^2 - \tilde\beta_{\text{rate}}\log_2 p^{(m)}_j - 2(\tilde z^{(m)}_{e,u,v}-z_0)^T(\tilde e^{(m)}_j - z_0) \right]$$
  **码字范数项与先验项离线预计算**，只有**点积项**由既有 PW MAC 阵列计算；偏置相加与取最小值的比较由辅助逻辑完成。
- **码本基数精简（训练后）**：参考量化器 $(M_0, K_0, D_{m,0}) = (4, 256, 16)$，未编码码率上界 $32/64 = 0.5$ bpp；训练后按 EMA 使用先验对每个子码本的 256 个条目排序，仅保留前 $K$ 个（$K \in \{256,128,96,64,32\}$），先验重新归一化；**不使用评估集分配来选择保留码字**。最终选定 $(M^\star, K^\star, D^\star_m) = (4, 64, 16)$，即每个潜在位置 4 个 6-bit 索引（24 bit，固定宽度 0.375 bpp）。
- **硬件收益的解析规律**：穷举打分需 $N_{\text{mul,VQ}} = M K D_m = DK$ 次标量乘法/潜在位置，码本也存 $DK$ 个标量，索引需 $M\lceil \log_2 K\rceil$ bit。固定 $D=64$、$(M,D_m)=(4,16)$ 时，减小 $K$ 使算术、码本存储与索引位宽**线性下降**。

### 2.4 云端解码器与训练目标
