## 摘要
极端压缩技术，包括向量量化（VQ）和输入相关稀疏性，可以显著降低大语言模型（LLM）的内存占用。然而，如何将这种压缩转化为实际效率仍是一个关键挑战。在传统的基于脉动阵列的加速器上，VQ 会带来高昂的反量化开销，而输入相关稀疏性的不规则模式难以被有效利用。在本研究中，我们通过 Vortex 应对这些挑战。Vortex 是一种与基于脉动阵列的加速器兼容、且硬件开销极小的架构，弥合了极端压缩与高效推理之间的差距。Vortex 采用双流执行策略，可在预填充（prefill）和解码（decoding）工作负载中高效支持向量量化模型，并且我们通过系统化的设计空间探索对其进行了进一步优化。在算法方面，我们提出码本级上下文稀疏性，以与 VQ 执行对齐。在端到端工作负载中，Vortex 相比最先进的加速器实现了 8.03 倍至 23.7 倍的加速，以及 5.68 倍至 12.5 倍的能耗降低。

## Abstract
Extreme compression techniques, including vector quantization (VQ) and input-dependent sparsity, can significantly reduce the memory footprint of large language models (LLMs). However, a key challenge remains in translating such compression into practical efficiency. On conventional systolic-array-based accelerators, VQ incurs high dequantization overhead, while the irregular patterns of input-dependent sparsity are difficult to exploit. In this study, we address these challenges with Vortex, an architecture compatible with systolic-array-based accelerators with minimal hardware overhead, bridging the gap between extreme compression and efficient inference. Vortex adopts a bi-flow execution strategy that efficiently supports vector-quantized models across both prefill and decoding workloads, and we further optimize it through systematic design space exploration. On the algorithm side, we propose codebook-wise contextual sparsity to align with VQ execution. Across end-to-end workloads, Vortex achieves $8.03\times$--$23.7\times$ speedup and $5.68\times$--$12.5\times$ energy reduction over state-of-the-art accelerators.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 规模迅速膨胀，部署受限于内存占用与推理效率。现有压缩路线主要有两条：
  - **量化**：从解析量化（均匀/浮点，4-bit 左右有效）走向**码本（向量）量化（VQ）**，通过学到的码本以索引表示权重，可压到 sub-2-bit，降低片外访存。
  - **稀疏**：关注**输入相关（上下文）稀疏**，即依据激活幅度动态剪枝，可带来 30–50% 的计算削减，且无需永久修改权重。
- **核心矛盾**：极端压缩在算法上成立，却难以在传统脉动阵列（systolic array）硬件上转化为实际效率：
  - **VQ 反量化开销高**：码本查找是不连续、不规则访问，多个 PE 并发查找会引发严重 bank 冲突，并行度与吞吐受限；实测 Llama2-7B 的 2-bit AQLM 端到端反而比 FP16 慢 **1.88×**。
  - **KV cache 动态性**：KV 在运行时生成，需要高通量在线量化器，仅优化静态权重不足以突破内存墙。
  - **输入稀疏难利用**：细粒度、逐 token 动态决策，与批量执行模型错配；batch 增大时需取多 token 稀疏模式交集，交集迅速缩小——batch 从 1 增到 16，有效稀疏率从 30.4% 骤降至 5.1%，导致稀疏实际只在 batch=1 有效。
- **整体含义**：论文主张必须做**压缩算法—执行流—硬件**的协同设计，才能真正把极端压缩转化为可落地的推理加速；Vortex 即为此提出的统一架构方案。

## 2. 方法论

### 2.1 核心思想

- 在**兼容现有脉动阵列**的前提下，仅以极小硬件开销新增三个单元，统一支持静态权重量化、动态 KV cache 量化与运行时输入稀疏。
- **双流执行策略（bi-flow）**：针对 prefill 与 decoding 两种截然不同的负载特征，分别采用 LUF 与 MUF 两条执行流，并在同一硬件上按 batch size 切换，无额外切换开销。

### 2.2 硬件单元

- **LUU（Lookup Unit）**：多个 SRAM bank 分区存储码本，支持并行查找；通过将码本复制 $a/v$ 倍以匹配 $a$ 宽 MXU 数据通路，消除 bank 冲突。码本本身很小，可全片上存放并复制。
- **VPU（Vector Processing Unit）扩展**：加宽为 4×32 宽 FP16 加法树，并引入缩放因子 $s$ 调节 VPU/LUU 并行度，平衡三段流水。
- **QAU（Quantization Unit）**：类一维脉动阵列的在线量化单元，含 16 个 matcher，每个 matcher 含比较器、待量化激活 buffer 和最小距离/质心索引寄存器。流程为三步：(1) 新生成 KV 激活按长度 $v$ 分块存入 matcher；(2) 码本质心流式扫过各 matcher，计算 $\ell_2$ 距离并更新寄存器；(3) 输出最近质心索引。吞吐为每 $2^b$ 周期量化 $N_{matchers}$ 个向量，且延迟可与 MXU/LUU 执行重叠。
- **SPU（Sparsity Unit）**：运行时计算块重要性、生成稀疏掩码、转换为向量索引并做 gather/regroup，再由 MUF 流逐 token 处理。

### 2.3 双执行流与设计空间

- **LUF（Lookup-First）**：先用 LUU 解码重建权重 tile，再交 MXU 做标准 MAC（输出固定、$a\times a$ 分块、沿 K 流式）。保持标准脉动阵列模型，$M$ 大时高效。
- **MUF（Multiply-First）**：不重建权重。将输入行按 $v$ 分块，与码本相乘生成**部分和码本** $P$，再用权重索引查表并沿 $a$ 维累加，形成“乘—查—累加”三段流水；枚举码本所有可能值以提升复用。
- **关键参数选择（经系统设计空间探索）**：
  - **向量长度 $v=8$（算法约束）**：$v$ 从 8 增到 16 会导致 PPL 大幅恶化（如 Llama-2-7B 从 5.68 升至 9.21），故取 8。
  - **索引位宽 $b=8$（硬件约束）**：$b=16$ 时码本达 MB 级不可行；拆成 $n=2$ 个 $b=8$ 码本可将查找成本降约 128×，码本从 MB 级降到 KB 级，PPL 仅从 5.68 微增至 5.90。
  - **VPU 缩放因子 $s=4$**：计算侧允许 $s\in[1,16]$；但受 DRAM 带宽约束 $a\cdot s\cdot b \le 2a\cdot16$，即 $s\le 32/b=4$，故取 4。
  - **流切换点 $M=16$**：推导得 LUF/MUF 比值与 $N,K,a$ 无关；$M<16$ 时 MUF 更优，$M>16$ 时 LUF 更优，$M=16$ 为平衡点。
- **多码本处理**：LUF 把码本视为**空间维度**、在 GEMM 前累加（一次 GEMM 覆盖所有码本）；MUF 视为**时间维度**、在 GEMM 后累加，串行执行、延迟随 $n$ 线性增长。

### 2.4 算法侧：码本级上下文稀疏

- **向量粒度稀疏**：将输入按 VQ 向量长度 $v$ 分块 $\mathbf{x}^{(g)}$，以块为单位整体剪枝，与 VQ 粒度对齐。
- **块重要性函数** $\phi(\mathbf{x}^{(g)})$：候选有 $\ell_1$、$\ell_2$、$\ell_\infty$ 范数；敏感性研究表明三者性能相近。
