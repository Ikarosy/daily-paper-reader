## 摘要
极端压缩技术，包括向量量化（VQ）和输入相关稀疏性，可以显著降低大语言模型（LLM）的内存占用。然而，如何将这种压缩转化为实际效率仍是一个关键挑战。在传统的基于脉动阵列的加速器上，VQ 会带来高昂的反量化开销，而输入相关稀疏性的不规则模式也难以被利用。在本研究中，我们通过 Vortex 应对这些挑战，Vortex 是一种与基于脉动阵列的加速器兼容且硬件开销极低的架构，弥合了极端压缩与高效推理之间的差距。Vortex 采用双流执行策略，可在预填充和解码工作负载中高效支持向量量化模型，并且我们通过系统性的设计空间探索对其进一步优化。在算法层面，我们提出了码本级上下文稀疏性，以与 VQ 执行对齐。在端到端工作负载上，Vortex 相比最先进的加速器实现了 8.03×–23.7× 的加速和 5.68×–12.5× 的能耗降低。

## Abstract
Extreme compression techniques, including vector quantization (VQ) and input-dependent sparsity, can significantly reduce the memory footprint of large language models (LLMs). However, a key challenge remains in translating such compression into practical efficiency. On conventional systolic-array-based accelerators, VQ incurs high dequantization overhead, while the irregular patterns of input-dependent sparsity are difficult to exploit. In this study, we address these challenges with Vortex, an architecture compatible with systolic-array-based accelerators with minimal hardware overhead, bridging the gap between extreme compression and efficient inference. Vortex adopts a bi-flow execution strategy that efficiently supports vector-quantized models across both prefill and decoding workloads, and we further optimize it through systematic design space exploration. On the algorithm side, we propose codebook-wise contextual sparsity to align with VQ execution. Across end-to-end workloads, Vortex achieves $8.03\times$--$23.7\times$ speedup and $5.68\times$--$12.5\times$ energy reduction over state-of-the-art accelerators.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 规模迅速增长，部署受内存占用与带宽限制。极端压缩技术（向量量化 VQ、输入相关稀疏性）理论上可大幅降低内存占用，但**难以转化为实际推理加速**。
- **核心矛盾**：
  - **VQ 的反量化开销**：码本查找（lookup）是不连续、不规则的内存访问，在 GPU/脉动阵列上导致严重访存冲突，并行度与吞吐受限。实测 2-bit AQLM 量化的 Llama2-7B 端到端比 FP16 **慢 1.88×**。
  - **工作负载不均衡**：LUT 类范式（预计算部分和再查表）把瓶颈从矩阵乘单元转移到累加单元，仍存在利用率低的问题。
  - **KV Cache 动态性**：长上下文场景下 KV Cache 成为内存消耗主体，且运行时动态生成，需要高吞吐的在线量化器。
  - **输入稀疏性两大障碍**：(a) 与 VQ 的向量粒度不匹配（元素级 vs 向量级）；(b) 批处理下多 token 稀疏模式差异大，取交集后有效稀疏率随 batch 增大迅速衰减（batch=8 时仅剩约 5–9%），实际只在 batch=1 有效。
- **整体含义**：论文旨在通过**稀疏性、量化、硬件执行的统一协同设计**，弥合"极端压缩"与"高效推理"之间的鸿沟，尤其面向资源受限的边缘平台。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体架构（兼容脉动阵列，最小硬件改动）
在传统脉动阵列（MXU）基础上增加三个单元：
- **LUU（Lookup Unit）**：多 SRAM bank 分区存储码本，支持并行码本查找，缓解访存冲突。
- **QAU（Quantization Unit）**：一维脉动阵列式匹配器（comparator + buffer + 距离/索引寄存器），支持 KV Cache 在线 VQ。
- **SPU（Sparsity Unit）**：运行时检测并剪枝低重要性激活块。
- 同时扩展 **VPU（向量处理单元）**，加入缩放因子 `s` 调节并行度。

### 2.2 双流执行策略（Bi-flow vGEMM）
- **LUF（Lookup-First，查表优先）**：先经 LUU 解码重建权重 tile，再由 MXU 做标准 MAC（output-stationary）。码本按 `a/v` 复制以匹配 MXU 带宽。适合 **大 M（预填充）**，多码本时在 GEMM 前空间累加，一次 GEMM 完成。
- **MUF（Multiply-First，乘优先）**：将输入按 K 维切成 v 长度子向量，与码本相乘生成部分和码本 P，再用权重索引 Q 查表并沿 a 维累加。三阶段流水：乘 → 查 → 累加。适合 **小 M（解码）**，多码本时在 GEMM 后时间累加，延迟随 n 线性增长但无需额外硬件。
- **切换机制**：以 M=16 为平衡点（`LUF/MUF = v·s/(n·M)`，n=2, v=8, s=4 时 M=16 处相等）。M<16 用 MUF，M≥16 用 LUF；仅需换 kernel 与指令，无切换开销。

### 2.3 关键设计空间探索
- **向量长度 v=8**（算法约束）：v=16 时精度严重退化（Llama-2-7B PPL 从 5.68 升至 9.21）。
- **码本位数 b=8**（硬件约束）：b=16 码本达 1MB 不可行；用 n=2、b=8 分解，查找成本降低约 128×，PPL 仅从 5.68 升至 5.90，码本从 MB 级降至 KB 级。
- **VPU 缩放 s=4**：计算上 s∈[1,16]，但受 DRAM 带宽约束 `a·s·b ≤ 2a·16` → `s ≤ 32/b = 4`，故取 s=4。

### 2.4 KV Cache 压缩
- 采用 CQ 设计的 **CQ-4c8b** 配置（n=1, v=4, b=8）。
- QAU 流程：KV 激活切分为 v 长度向量存入 matcher → 码本流式遍历，计算 ℓ2 距离并更新最小距离寄存器 → 输出最近质心索引。
- 吞吐为每 2^b 周期量化 N_matcher 个向量，通过质心复用降低 SRAM 带宽与功耗，延迟与 MXU/LUU 重叠。

### 2.5 码本级上下文稀疏性（Codebook-wise Contextual Sparsity）
- **粒度对齐**：把输入激活按 VQ 向量长度分块 `x⁽ᵍ⁾ ∈ R^(1×v)`，整块剪枝，实现结构化跳过。
- **块重要性函数 φ**：ℓ1/ℓ2/ℓ∞ 范数（三者效果相近，取 ℓ1）。
- **码本差异化阈值**：RVQ 中前序码本捕捉主成分、后序码本修正残差，故为每个码本分配不同稀疏率 ρᵢ（重要码本保守剪枝）。判定式：`σᵢ(x⁽ᵍ⁾, ρᵢ) = I[φ(x⁽ᵍ⁾) ≥ tᵢ]`，阈值 tᵢ 由分位数确定。
- **阈值搜索**：贪心策略，仅用 64 个 WikiText 样本校准，逐个 Transformer block 联合优化全部 14 个阈值（7 个 FC 层 × 2 码本），每轮选择 MSE 增幅最小的候选提升稀疏度。
- **批处理下的稀疏保持**：MUF 逐 token 计算，被剪枝块无需访问对应权重行，不同 token 的稀疏模式差异不会互相干扰，从而在任意 batch 下保持规则访问模式。

## 6. 主要结论与发现

- 端到端工作负载上，Vortex 相比最先进加速器实现 **8.03×–23.7× 加速**和 **5.68×–12.5× 能耗降低**。
- 相比传统脉动阵列平均 **22.4× 加速、9.75× 能耗降低**；相比 FIGLUT 达 **8.03× 加速、5.68× 能耗降低**。
- 性能增益分解：权重量化贡献 11.33×，KV Cache 量化额外 1.66×（累计 18.8×），激活稀疏再贡献 1.19×（累计 22.4×）；仅 FC 层时权重量化可达 31.1×，稀疏再带来 1.37×。
- 精度方面：码本级上下文稀疏在保持 AQLM 95% 相对精度下，Llama2-7B 可达 30% 稀疏、Llama2-13B 达 25%；相比码本均匀策略，同精度下可多挖掘最多 **10% 额外稀疏**（小模型收益更明显）。
- 结合激活稀疏后，batch=1 解码时**每参数有效位宽可降至 2 bit 以下**（PIQA 任务接近 1 bit 仍保持精度）。
- 面积效率 9.71 tokens/s/mm²，分别比 ANT、FIGNA、FIGLUT 高 11.9×、10.1×、4.42×。
- DRAM 占功耗 67%，说明访存仍是核心瓶颈，量化与稀疏减流量至关重要。

## 7. 优点

- **统一协同设计**：将权重 VQ、KV Cache 在线量化、输入稀疏三者与硬件执行流统一，覆盖静态参数与动态数据。
- **双流架构适配性强**：MUF/LUF 分别针对解码（小 M）与预填充（大 M），切换零开销，充分利用两种执行流的互补性，且理论分析（公式推导）与实验（batch 扫描）高度一致。
- **粒度对齐的算法创新**：提出码本级上下文稀疏，解决 VQ（向量级）与稀疏（元素级）的粒度错配，且为 **免训练** 机制。
- **批处理下稀疏有效性**：通过 MUF 逐 token 计算绕过跨 token 交集衰减问题，突破稀疏仅在 batch=1 有效的传统局限。
- **硬件开销小**：仅增加 LUU/QAU/SPU 与 VPU 轻量扩展，兼容现有脉动阵列，面积效率显著优于基线。
- **设计空间探索系统**：对 v、b、s、M 阈值均有量化推导与实验验证，指导性强。

## 8. 不足与局限

- **缺乏真实硅验证**：性能来自周期精确模拟器 + RTL 综合估算，未流片或实机测量，实际性能可能与仿真存在差距。
- **模型规模有限**：仅验证到 7B–13B，未覆盖更大模型（如 70B+）或 MoE 架构，可扩展性待验证。
- **基线位宽不对等**：Vortex 使用约 2-bit 甚至更低，而部分基线为 W4A16/W8A8，加速比中位宽优势占比大，跨位宽对比的公平性有限。
- **稀疏未应用于 KV Cache**：论文明确指出激活稀疏未用于 KV Cache，削弱了端到端收益（如注意力密集场景稀疏仅贡献 1.17×）。
- **稀疏水平受精度约束**：仅取 30% 稀疏以保证精度，进一步稀疏的空间有限；阈值搜索依赖校准数据分布，泛化性存在潜在偏差风险。
- **KV Cache 量化沿用 CQ 设计**：未提出新的 KV 量化算法，创新度相对集中于权重侧。
- **依赖特定量化方案**：硬件配置（v=8, b=8, n=2）与 AQLM checkpoint 强绑定，对其它 VQ 方案（如不同 v/b 组合）的通用性需进一步验证。
- **应用场景偏向边缘**：论文定位资源受限边缘平台，在高吞吐数据中心场景下的收益比例可能下降。
- **能耗主因仍是 DRAM（67%）**：片上计算优化对整体能耗改善存在上限。
