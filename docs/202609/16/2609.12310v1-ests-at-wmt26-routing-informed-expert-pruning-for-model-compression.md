## 摘要
我们描述了以团队名 ESTS 参加 WMT26 无约束模型压缩共享任务的六份提交，涉及英语—简体中文和英语—埃及阿拉伯语。我们为每个翻译方向提交三个压缩工作点，均基于 GPT-OSS-20B 得到。我们使用任务特定的路由质量（routing mass）对专家进行排序，并使用跨语言路由散度在各层之间分配保留容量，然后物理移除重要性低的专家。所得的专家模型在 GPT-5.1 生成的合成翻译数据上进行恢复微调，并通过将 MXFP4 量化应用于保留的专家投影权重来进一步压缩。我们还为指令条件化的 WMT26 设置实现了一个鲁棒的推理系统，包括类别推断、输出验证、重试、分段回退以及源端 JSON 重构。在我们的六份提交中，参数量从 4.186B 到 7.770B 不等，打包产物大小从 4.55 到 6.33~GiB 不等。使用 GPT-5.1 伪参考进行的内部 xCOMET-XL 评估为所提交的压缩工作点提供了内部比较。

## Abstract
We describe six submissions under the team name ESTS to the unconstrained WMT26 Model Compression Shared Task for English--Simplified Chinese and English--Egyptian Arabic. We submit three compression operating points per translation direction, all derived from GPT-OSS-20B. We use task-specific routing mass to rank experts and cross-lingual routing divergence to allocate retained capacity across layers, then physically remove low-importance experts. The resulting specialists are recovery-tuned on GPT-5.1-generated synthetic translation data and further compressed by applying MXFP4 quantization to the retained expert projection weights. We additionally implement a robust inference system for the instruction-conditioned WMT26 setting, including category inference, output validation, retries, segmented fallback, and source-owned JSON reconstruction. Across our six submissions, parameter counts range from 4.186B to 7.770B and packed artifact sizes from 4.55 to 6.33~GiB. Internal xCOMET-XL evaluation using GPT-5.1 pseudo-references provides an internal comparison across the submitted compression operating points.

- **整体含义**：论文主张"任务特定路由行为"可作为 MoE 专家重要性的可靠信号，从而在专家粒度上做结构化压缩，并与合成数据恢复微调、低比特量化结合，形成一条可生成多个压缩档（operating points）的流水线。

## 2. 方法论

### 2.1 核心思想

- 起点模型：**GPT-OSS-20B**（每 MoE 层 E=32 个专家，每 token 激活 K=4 个）。
- 用 **k ∈ [0, 28]** 表示每层平均剪除的专家数，据此派生不同压缩工作点。
- 两大路由信号：
  - **路由质量（routing mass）** → 层内专家排序（剪掉最不重要的）；
  - **跨语言路由散度（cross-lingual routing divergence）** → 跨层分配保留容量（语言特化层保留更多专家）。
- 剪枝后做**恢复微调（recovery SFT）**，再对保留的专家投影权重做 **MXFP4 量化**。

### 2.2 关键细节

- **路由质量**：对第 ℓ 层 token i 的专家 ε，其输出权重 w^ℓ_{i,ε} 由归一化 top-K 路由权重给出（非激活专家为 0，全体求和为 1）；对整条序列做均值聚合即得该专家的 routing mass。统计用 vLLM + PyTorch hooks 实现。
- **校准数据**：每个翻译方向取 **660 条**任务相关样本，类别配额近似按全量数据的 prompt+target token 数比例采样。
- **层容量分配**：用目标语言与英语路由分布之间的 **Jensen–Shannon 散度** d^s_ℓ ∈ [0,1]（不做熵归一化，区别于 Bandarkar et al. 2026），在 4,400 对英–中序列（ZHO）与 9,999 对英–埃阿序列（ARZ）上估计。
  - 总预算 C = L(E − k)；每层先初始化为下限 K；剩余预算 B = C − LK 按 d^s_ℓ 比例分配；超出上限 E 的部分溢出回收再分配；最后用 **Hamilton 法**取整，满足 K ≤ c_ℓ ≤ E 且总和守恒。
  - 层 ℓ 剪除 k_ℓ = E − c_ℓ 个 routing mass 最低的专家。
- **物理移除**：沿 dim 0 切分 `experts.gate_up_proj`、`experts.down_proj` 及对应 bias、`router.weight`、`router.bias`；由于各层专家数不同，用配置中的列表记录每层专家数，自定义 modeling 文件按层读取，可被标准 Transformers 加载路径直接加载。
- **恢复微调**：LLaMA-Factory，BF16，最大序列 4096，LR 5×10⁻⁶（linear schedule + 5% warmup），per-device batch size 1，梯度累积 3 步；**全参数微调**（而非 PEFT），因为目标是从整块专家参数删除后恢复能力。
- **MXFP4 量化**：用 NVIDIA ModelOpt 对保留专家的 `gate_up_proj` / `down_proj` 做 32 值分块的 MXFP4 后训练量化；注意力、embedding、router 参数、专家 bias、LM head 保持 BF16，形成混合精度存储。

### 3.4 推理系统（面向指令条件化设置）

- **类别推断**：确定性启发式。可解析的 JSON/数组/代码围栏 → JSON；含 `<br>` 或 handle/hashtag/URL/emoji 的 HTML → social；`<p>` 块 ≤5 且首段不像新闻标题的 HTML → social；其余 HTML → news；无标签纯文本 → speech。JSON 走特殊处理，其余前置对应 WMT26 指令。
- **生成与校验**：vLLM + OpenAI Harmony 格式，low reasoning effort，temperature 0.5，输出上限 8,192 tokens；优先取 Harmony final channel，解析失败时可接受无 scaffold 标记的干净原始补全；每条输入最多 **10 次**整单元尝试（seed 0–9），仅对未解决样本重试；拒绝空输出、不可恢复 Harmony、触顶、严重重复、结构校验失败（新闻/社交须保持段落与换行结构）。
- **分段回退**：10 次失败后，HTML 依次按顶层 `<p>`、`<br>` 切分，再按句子边界，最后按约 300 字符（<400 字符）的完整词跨度切分；每段包 `<p>` 并用原类别指令翻译（上限 2,048 tokens，seed 0–4），再按源结构重组；仍失败则退回最佳非空原始补全，最后退回源文。
- **JSON 投影与重构**：不直接让模型生成 JSON，而是解析源串、抽取各字符串值及其 JSON 路径，投影为 `<p>` 块（换行→`<br>`）用 news 指令翻译后按路径写回源结构副本；占位符原样传入并做保守修复与校验；失败则逐字符串重试，再失败则绕占位符切分，未解决跨度保留源文；输出前对键与顺序、数组结构、非字符串值、占位符做校验，**由源端结构序列化，因此不会产出畸形 JSON**。
