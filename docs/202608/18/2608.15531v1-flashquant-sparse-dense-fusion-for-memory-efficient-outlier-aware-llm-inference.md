## 摘要
低比特量化降低了大型语言模型（LLM）推理的内存占用和计算成本。然而，高幅度的离群权重会引入显著的量化误差并降低模型精度。离群感知量化通过将离群值保持在高精度同时对剩余权重进行量化来解决该问题，从而形成低比特稠密GEMM路径和高精度稀疏SpMM路径。现有实现将这些路径在单独的GPU内核中执行，尽管它们共享激活和输出，从而错失了算子内复用的机会，并导致冗余的全局内存访问。这种低效在内存受限的解码工作负载中尤为突出。我们提出了FlashQuant，一种用于离群感知W4A16解码的内容共享执行框架。FlashQuant将稠密GEMM和稀疏离群SpMM路径融合到单个GPU内核中，从而在异构计算之间实现激活和输出块的片上复用。它引入了三项关键技术：稀疏-稠密分块，将离群处理与稠密GEMM块对齐；Tile-COO离群编码，实现高效的稀疏访问并减少共享内存存储体冲突；以及流水线调度，将计算与数据移动重叠。实验表明，FlashQuant降低了离群处理开销，与cuBLAS BF16相比实现了$2.74\times - 4.18\times$的加速，与最强的未融合离群感知基线相比实现了最高$1.53\times$的加速。

## Abstract
Low-bit quantization reduces the memory footprint and computational cost of large language model (LLM) inference. However, high-magnitude outlier weights can induce substantial quantization errors and degrade model accuracy. Outlier-aware quantization addresses this issue by retaining outliers in high precision while quantizing the remaining weights, resulting in a low-bit dense GEMM path and a high-precision sparse SpMM path. Existing implementations execute these paths in separate GPU kernels, despite their shared activations and outputs, thereby missing opportunities for intra-operator reuse and incurring redundant global-memory accesses. This inefficiency is particularly pronounced in memory-bound decoding workloads. We propose FlashQuant, a content-sharing execution framework for outlier-aware W4A16 decoding. FlashQuant fuses the dense GEMM and sparse outlier SpMM paths into a single GPU kernel, enabling on-chip reuse of activation and output tiles across heterogeneous computations. It introduces three key techniques: sparse-dense tiling, which aligns outlier processing with dense GEMM tiles; Tile-COO outlier encoding, which enables efficient sparse access and reduces shared-memory bank conflicts; and pipelined scheduling, which overlaps computation with data movement. Experiments show that FlashQuant reduces outlier-processing overhead, achieving $2.74\times - 4.18\times$ speedup over cuBLAS BF16 and up to $1.53\times$ speedup over the strongest unfused outlier-aware baseline.

## 一、核心问题与研究动机

### 背景与问题
- **低比特量化**（如 INT4）被广泛用于降低 LLM 推理的内存占用和计算成本，但其对**高幅值离群权重**非常敏感，量化这些离群值会引入严重的重建误差，导致模型精度明显下降。
- **离群感知量化**（Outlier-Aware Quantization）通过将少部分离群权重保留在高精度（如 BF16）、其余权重低比特量化的方式，在精度与压缩率之间取得更优平衡。例如，对 LLaMA3-8B 保留 1% 离群值进行 INT4 量化，可将 WikiText2 困惑度从 6.896 降至 5.979。

### 核心瓶颈
- 离群感知量化将原始矩阵乘法分解为两条计算路径：
  - **低比特稠密 GEMM** 路径（处理量化后的权重矩阵）；
  - **高精度稀疏 SpMM** 路径（处理离群权重矩阵）。
- **现有实现将这两条路径作为独立 GPU 内核分别执行（如 cuSPARSE + Marlin），存在显著的低效问题：**
  - 两条路径共享相同的激活矩阵和输出矩阵，但分开执行导致激活块被重复从全局内存加载；
  - 部分输出结果独立写回，产生冗余的内存流量；
  - 在**内存受限的解码阶段**，即使离群值占比很小，也会造成不成比例的推理延迟。

### 论文定位
- 作者指出这不是传统的"生产者-消费者算子融合"，而是**内容共享融合（content-sharing fusion）**——将源自同一数学算子的两条异构计算路径，在统一的块级执行空间上协同调度，实现片上数据复用。

## 二、方法论

### 总体框架
FlashQuant 分为**离线预处理**和**在线推理**两个阶段：

1. **离线阶段**：执行离群感知量化，将权重矩阵分解为量化矩阵 $W_Q$ 和稀疏离群矩阵 $W_O$；应用统一的分块方案并生成 Tile-COO 编码。
2. **在线阶段**：将稠密 GEMM 和稀疏 SpMM 融合到**单个 GPU 内核**中执行，激活矩阵加载到共享内存后由两条路径共同消费，部分结果先片内累加再写回。

### 核心公式
离群感知量化的分解形式为：

$$Y = X \cdot W \approx X \cdot \text{dequant}(W_Q) + X \cdot W_O$$

### 三大关键技术

#### 1. 稀疏-稠密分块（Sparse-Dense Tiling）
在 **CTA 级**、**Warp 级**和 **Thread 级**三个层次上对齐稠密与稀疏计算：
- **CTA 级**：相同输出块的稠密和稀疏计算放置在同一 CTA，激活块只加载一次；采用 Stream-K 工作分配策略平衡负载。
- **Warp 级**：稠密路径使用 Tensor Core MMA 指令（Sliced-K 并行）；稀疏路径分配给独立 warp，运行于 CUDA Core，并按输出列分区避免写冲突；根据稀疏负载动态分配额外 warp。
- **Thread 级**：激活矩阵采用 8 元素 swizzle 布局减少 bank 冲突；稀疏路径每个子 warp 负责多个桶（bucket），每个桶映射到一组线程。

#### 2. Tile-COO 离群编码格式
为满足融合执行的四项要求（与 GEMM 块的边界对齐、元数据向量化访问、兼容共享内存激活布局、负载均衡），设计了 Tile-COO 格式：
- 由三个数组组成：**tile_indptr**（记录每个 tile 的偏移）、**bucket_info**（记录桶偏移和非零个数）、**packed_outliers**（打包的行索引、列索引和值）。
- 行索引和列索引均使用 **uint8_t**（共享内存 tile 最大 256×256），离群值用 **bfloat16**，每 4 个离群值打包为一个 uint4 元组。
- 总存储成本约为 $(N_{tile}+1) \times 4 + N_B \times 4 + nnz \times 4$ 字节，相比 CSR（$(K+1) \times 4 + nnz \times 12$ 字节）大幅降低元数据开销。

#### 3. 稀疏重排序（Sparse Reordering）
- **列重排序**：按非零数量降序排列列，通过最小堆贪心调度将高密度列均匀分配到各桶，缓解负载不均。
- **元素重排序**：依据行索引的目标 bank 组对元素进行排序，采用依赖 bucket_id 的循环顺序，将不同子 warp 的访问错开，减少共享内存 bank 冲突（例如将冲突次数从 4 降至 1）。

#### 4. 流水线执行（Pipelined Execution）
- 四级流水线：全局内存加载 → 寄存器暂存 → 反量化与离群解码 → Tensor Core / CUDA Core 计算。
- 采用双缓冲机制，将数据移动与计算重叠，隐藏内存延迟。
- 离群解码使用预计算 swizzle 掩码，一次性应用于四个元素，解码后执行四次解卷的 FMA 指令。

## 六、主要结论与发现

1. **性能提升显著**：FlashQuant 相比 cuBLAS BF16 实现 **2.74×–4.18×** 加速；相比最强未融合离群感知基线（Sputnik+Marlin）在 RTX 4090 上实现 **1.12×–1.37×**、RTX 5090 上实现 **1.23×–1.53×** 加速。
2. **离群密度影响降低**：随着离群密度从 1.0% 到 3.0%，FlashQuant 的延迟增幅明显小于未融合基线，验证了融合执行在更高密度下的优势。
3. **新 GPU 架构优势放大**：在新一代 GPU（4090、5090）上，FlashQuant 的优势更显著，说明其减少内存流量的收益在高算力平台上更为突出。
4. **Tile-COO 存储效率高**：相比 CSR，Tile-COO 在 1.0%–3.0% 离群密度下的内存开销更低（元数据压缩有效）。
5. **端到端加速可观**：在 vLLM 上，FlashQuant 比 BF16 基线实现 **2.01×**（batch=8）和 **1.98×**（batch=16）的解码吞吐提升；同时使 Qwen2.5-14B 在内存受限情况下可从 OOM 变为可运行。
6. **精度保持良好**：离群感知量化相比 GPTQ 显著降低困惑度（如 LLaMA3-8B 从 6.896 降到约 5.93–5.98），仅引入少量内存开销。

## 七、方法优点

- **问题洞察准确**：精准识别出离群感知量化中稠密-稀疏分离执行导致的冗余内存访问这一系统级瓶颈，并量化了其影响。
- **融合设计创新**："内容共享融合"概念区别于传统算子融合，在统一内核中共享激活与输出数据，原理上具有通用性。
- **技术设计精细**：
  - 稀疏-稠密三级分块设计考虑周全（CTA 负载均衡采用 Stream-K，warp 级避免原子操作，thread 级减少 bank 冲突）；
  - Tile-COO 压缩率高且解码友好的编码设计巧妙（8-bit 索引、4 元素打包、双缓冲解码）；
  - 两阶段重排序（列均衡 + bank 冲突消解）针对 GPU 实际硬件特性进行了深度优化。
- **实验覆盖较广**：多 GPU 代际（Ampere、Ada Lovelace、Blackwell）、多模型家族、多 batch size 和多离群密度，结论具有较好的可信度和可迁移性。

## 八、不足与局限

- **小 batch 场景受限**：FlashQuant 将输入 padding 到最小 batch 8，在 batch ≤ 4 的极端场景下引入冗余计算，优势明显减弱；而实际生产环境中 batch=1 的自回归解码非常常见。
- **实验仅覆盖消费级 GPU**：未在数据中心级 GPU（如 A100、H100）上验证，这些平台的 SM 数量、内存带宽和 Tensor Core 规格不同，结论的泛化性有待进一步验证。
- **预处理成本未充分讨论**：虽然单矩阵预处理 <100 秒可摊销，但未分析在线动态量化/增量离群更新场景下的可行性，对动态离群分布变化的鲁棒性存疑。
- **与相关系统的对比不足**：未与同样面向离群感知/混合精度推理的 MixQ、FLUTE 等系统直接进行端到端或算子级对比，其相对优势的覆盖面有待明确。
- **资源信息不完整**：未报告训练/评测的总 GPU 小时数、能耗、功耗等资源指标，不利于从成本角度全面评估。
- **扩展方向未验证**：论文提出未来将扩展到 INT2 等更低精度格式，但当前结论只适用于 W4A16 场景，适用范围有限。
- **解码阶段索引格式选择**：Tile-COO 使用 8-bit 列索引的前提是共享内存 tile ≤ 256，若未来 block size 增大或为适配更大 tile 所需的高精度索引，格式可能需重新设计。

## 综合评价

FlashQuant 是一篇**系统优化导向的论文**，以扎实的 GPU 底层优化（分块、编码、调度、reordering）解决了离群感知量化推理中的一个实际性能瓶颈。其核心贡献——稠密 GEMM 与稀疏 SpMM 的"内容共享融合"——在问题识别、技术设计和实验验证方面均具有较高的完整性与说服力。主要短板在于小 batch 场景的适配性、数据中心 GPU 的缺失验证以及与相关系统的直接对比不足。总体而言，该工作对内存受限的大模型推理部署具有实际参考价值，并为后续混合精度量化推理系统的设计提供了新思路。
