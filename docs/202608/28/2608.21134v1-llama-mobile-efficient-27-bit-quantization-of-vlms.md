## 摘要
在移动设备上部署视觉语言模型（VLM）因其巨大的内存和计算需求而具有挑战性。我们提出了一种用于在资源受限硬件上高效推理的VLM量化框架。我们的方法结合了一种量化流程，该流程利用模型自身生成训练数据，且无需访问训练设置，并提出了一种新颖的每参数2.7位格式，支持在Arm CPU上高效执行。我们通过将Llama 3.2 11B视觉指令模型压缩至3.7 GB（采用8位激活）来验证我们的方法，在一组标准视觉问答任务上保持了强劲的性能。

## Abstract
Deploying vision-language models (VLMs) on mobile devices is challenging due to their significant memory and compute requirements. We present a framework for quantizing VLMs for efficient inference on resource-constrained hardware. Our approach combines a quantization pipeline that uses the model itself to generate training data and does not require access to the training setup, with a novel 2.7-bit-per-parameter format supporting efficient execution on Arm CPUs. We validate our approach by compressing the Llama 3.2 11B Vision Instruct model to 3.7 GB with 8-bit activations, preserving strong performance on a set of standard visual question answering tasks.

## 2. 方法论

论文提出了一个端到端量化框架，包含三个关键组件：

- **合成数据生成（Synthetic Data Generation）**：
  - 使用模型自身（bfloat16 教师模型）在 ImageNet 图像上生成问答型响应，作为知识蒸馏的训练目标。
  - 通过随机化**提示词采样**（而非固定单一提示）增加数据多样性，如随机应用指令模板、加入长度约束、格式约束、响应风格指令等。
  - 该流程完全避免使用下游任务数据或基准特定的提示词，避免过拟合评估集。

- **量化感知训练（QAT）**：
  - 目标函数为学生模型与教师模型在生成的响应 token 上的 KL 散度蒸馏损失。
  - 学生模型前向传播使用量化后的权重（直通估计器传递梯度），主权重以 float32 保存。
  - 学习率根据平均比特数按启发式缩放（$\eta = 2^{-(b+14)}$）。

- **S3D8 格式（signed 3D 8-bit format）**：
  - 每字节存储 **3 个权重**：5 位共享质心索引 + 3 位各元素符号位，平均约 2.7 bit/参数（含通道缩放时约 2.68 bit/参数）。
  - 量化分两阶段：先用 Lloyd-Max/k-means++ 在归一化权重上拟合 32×3 质心表，QAT 阶段冻结质心，更新通道缩放、量化索引和符号。
  - **硬件协同设计**：利用 Arm Advanced SIMD 的 TBL 64 项表查找指令直接解码带符号值，仅需 5 条逻辑指令生成 3 个查找索引，解码 48 个元素；按输出通道打包避免归约轴上的 padding 逻辑。
  - 计算格式为 INT8，支持 Arm dotprod/i8mm 扩展，具有较高算术吞吐。

## 6. 主要结论与发现

- **S3D8 在亚 3 比特条件下显著优于 INT、student-t 和 lloyd-max 格式**：在 2.68 bit/参数下平均任务下降仅 0.083（0.744→0.661），而 INT 同尺寸下降至 0.347、lloyd-max 仅 0.436。
- **QAT 在极低比特下优于 GPTQ**：约 2.7 bit/参数时，S3D8+GPTQ 平均性能为 0.340，S3D8+QAT 为其近两倍（0.661）。
- **扩散提示采样对 QAT 至关重要**：固定提示（"Describe the image:"）训练导致下游性能大幅下降。
- **运行时性能验证有效**：S3D8 在文本生成（m=1 的矩阵乘）场景下快于 INT8（Pixel 8a 上 33.8 vs 26.5 GMAC/s），端到端在 Pixel 8a 上实现 3.8 tokens/s，在 Graviton4 上实现 36.8 tokens/s（INT8 为 26.4 tokens/s）。

## 7. 优点

## 8. 不足与局限
