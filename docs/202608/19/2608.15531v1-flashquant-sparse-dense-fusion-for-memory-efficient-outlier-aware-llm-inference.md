## 摘要
低比特量化减少了大型语言模型（LLM）推理的内存占用和计算成本。然而，高幅度异常值权重可能引发显著的量化误差并降低模型精度。异常值感知量化通过在高精度下保留异常值同时对剩余权重进行量化来解决此问题，从而产生低比特稠密GEMM路径和高精度稀疏SpMM路径。现有实现尽管共享激活和输出，但仍在单独的GPU内核中执行这些路径，因而错失了操作内复用的机会，并导致冗余的全局内存访问。这种低效在内存受限的解码工作负载中尤为突出。我们提出了FlashQuant，一种用于异常值感知W4A16解码的内容共享执行框架。FlashQuant将稠密GEMM和稀疏异常值SpMM路径融合到单个GPU内核中，从而在异构计算之间实现激活和输出瓦片的片上复用。它引入了三项关键技术：稀疏-稠密平铺（将异常值处理与稠密GEMM瓦片对齐）、Tile-COO异常值编码（实现高效稀疏访问并减少共享内存存储体冲突），以及流水线调度（将计算与数据移动重叠）。实验表明，FlashQuant降低了异常值处理开销，相较于cuBLAS BF16实现了2.74倍至4.18倍的加速，相较于最强的未融合异常值感知基线实现了最高1.53倍的加速。

## Abstract
Low-bit quantization reduces the memory footprint and computational cost of large language model (LLM) inference. However, high-magnitude outlier weights can induce substantial quantization errors and degrade model accuracy. Outlier-aware quantization addresses this issue by retaining outliers in high precision while quantizing the remaining weights, resulting in a low-bit dense GEMM path and a high-precision sparse SpMM path. Existing implementations execute these paths in separate GPU kernels, despite their shared activations and outputs, thereby missing opportunities for intra-operator reuse and incurring redundant global-memory accesses. This inefficiency is particularly pronounced in memory-bound decoding workloads. We propose FlashQuant, a content-sharing execution framework for outlier-aware W4A16 decoding. FlashQuant fuses the dense GEMM and sparse outlier SpMM paths into a single GPU kernel, enabling on-chip reuse of activation and output tiles across heterogeneous computations. It introduces three key techniques: sparse-dense tiling, which aligns outlier processing with dense GEMM tiles; Tile-COO outlier encoding, which enables efficient sparse access and reduces shared-memory bank conflicts; and pipelined scheduling, which overlaps computation with data movement. Experiments show that FlashQuant reduces outlier-processing overhead, achieving $2.74\times - 4.18\times$ speedup over cuBLAS BF16 and up to $1.53\times$ speedup over the strongest unfused outlier-aware baseline.

# FlashQuant 论文总结

## 1. 核心问题与整体含义

### 研究背景与动机

- **问题背景**：大型语言模型（LLM）推理面临巨大的内存和计算开销。例如，Qwen3-235B 在 BF16 精度下需要超过 470GB 内存，远超主流 GPU（如 NVIDIA A100）的显存容量。
- **低比特量化的局限**：权重量化（如 INT4）虽能显著降低内存占用，但高幅值**异常值权重（outlier weights）**会带来严重的量化误差，损害模型精度。
- **异常值感知量化的方案与代价**：通过保留少量（如 1%）高幅值权重为高精度（BF16）来缓解量化误差（例如 LLaMA3-8B 的 WikiText2 困惑度从 6.896 降至 5.979）。但该方案将计算分解为**低比特稠密 GEMM** 与**高精度稀疏 SpMM** 两条路径：
  - 现有系统（如 SpQR、SqueezeLLM 等）在**独立 GPU 内核**中分别执行这两条路径；
  - 两条路径共享相同的输入激活矩阵和输出矩阵，分离执行导致**激活矩阵的重复读取**与**中间结果的冗余全局内存写入**；
  - 在内存受限的解码（decoding）阶段，这种冗余访存开销使少量异常值也带来不成比例的延迟。

### 核心论点

> 现有异常值感知量化系统忽略了密集 GEMM 与稀疏 SpMM 之间的**数据共享机会**。FlashQuant 的核心主张是：通过将两条计算路径融合进**单个 GPU 内核**，实现激活与输出块的片上复用，可从本质上消除冗余内存访问。

## 2. 方法论：FlashQuant 框架

### 整体架构

FlashQuant 面向 **W4A16**（INT4 权重 + BF16 激活）解码场景，分两个阶段：

1. **离线预处理**：异常值感知量化 → 稀疏-稠密分块 → Tile-COO 编码与重排序；
2. **在线推理**：单内核融合执行（稠密 GEMM 路径 + 稀疏 SpMM 路径）。

### 技术一：稀疏-稠密分块（Sparse-Dense Tiling）

为兼容密集 GEMM 与稀疏 SpMM 两种异构执行模式，FlashQuant 构建了统一的分块层级：

| 层级 | 稠密路径 | 稀疏路径 |
|------|---------|---------|
| **CTA 级** | 按输出分块，采用 Stream-K 工作分配策略，确保持久 CTA 负载均衡 | 与稠密分块对齐，共享同一激活瓦片 |
| **Warp 级** | Tensor Core MMA 指令，采用 Sliced-K 并行 | CUDA 核执行，按输出列分配不相交集合，避免原子操作与写冲突 |
| **线程级** | 映射到 Tensor Core 的 16×16×8 MMA 布局 | 每桶（bucket）8 线程，按列分区，避免 bank 冲突 |

核心思路：**同一个激活瓦片只从全局内存加载一次，两条路径在片上共享**；局部结果在片上累加后才写回全局内存。

### 技术二：Tile-COO 异常值编码

针对常规稀疏格式（CSR 等）无法满足融合执行要求（tile 对齐、向量化访问、兼容共享内存布局、负载均衡）的问题，提出 **Tile-COO** 格式：

- **结构**：由三个数组构成——`tile_indptr`（tile 偏移）、`bucket_info`（桶偏移+非零数）、`packed_outliers`（打包的行/列索引+BF16 值）；
- **压缩编码**：行/列索引用 **uint8_t**（共享内存 tile 最大 256×256），每 4 个异常值打包为一个 uint4 元组，支持向量化解码；
- **存储优势**：相比 CSR 大幅减少元数据开销——CSR 需 `(K+1)×4 + nnz×12` 字节，Tile-COO 仅需 `(N_tile+1)×4 + N_B×4 + nnz×4` 字节。

### 技术三：重排序优化（Sparse Reordering）

- **列重排序**：按非零数量降序排列，用贪心堆调度将高密度列均匀分配到各桶，均衡子 warp 间负载；
- **元素重排序**：根据目标共享内存 bank 组（gid = k/2 % 4）进行循环轮转排序，降低跨子 warp 的 bank 冲突。

### 技术四：流水线调度（Pipelined Execution）

- 采用**双缓冲 + 多级流水线**：全局内存加载 → 寄存器暂存 → 反量化/异常值解码 → Tensor Core/CUDA Core 计算，四个阶段重叠执行，隐藏内存延迟；
- 为稀疏路径**分配额外的 warp**（对访存延迟更敏感），利用 warp 级上下文切换提升延迟容忍度。

### 核心公式

**异常值感知分解**：Y = X·W ≈ X·dequant(W_Q) + X·W_O

其中 W_Q 为低比特稠密权重矩阵，W_O 为稀疏高精度异常值矩阵。

## 7. 优点

1. **问题识别精准**：明确指出分离执行导致的冗余内存访问是异常值感知量化的关键系统瓶颈，这是一个有价值且此前未被系统化解决的问题；
2. **"内容共享融合"概念新颖**：不同于常规的 producer-consumer 内核融合，FlashQuant 融合的是同一算子内部的两条异构计算路径（GEMM + SpMM），具有方法论创新性；
3. **技术栈完整且协同良好**：从分块策略（Tile 级别对齐）、数据格式设计（Tile-COO）、负载均衡（重排序）到执行调度（流水线），各技术环环相扣，构成完整解决方案；
4. **Tile-COO 存储高效**：利用 tile 局部性和低精度索引，相比 CSR 显著降低元数据开销和存储成本；
5. **硬件适配性强**：在三代 GPU（Ampere、Ada Lovelace、Blackwell）上均有效，且在新 GPU 上优势更明显；
6. **实验规范**：消融实验合理，能清晰分解各优化技术的贡献。

## 8. 不足与局限

- **Batch size 覆盖不完整**：未测试大于 32 的 batch；在 batch size 1–2 时因 padding 到 8 导致性能优势减弱甚至可能劣于基线（论文仅承认"优势减弱"，未量化损失幅度）；

- **模型覆盖有限**：端到端仅验证了 LLaMA3-8B 和 Qwen2.5-14B，未包含更大规模模型（论文开头提到的 Qwen3-235B 等）；

- **未对比更近期方法**：论文仅对比 Marlin、Sputnik、cuSPARSE，未与 MixQ、FLUTE 等做定量对比（仅在相关工作部分讨论）。

### 方法内部局限

- **仅支持 W4A16**：当前只针对 INT4 权重量化 + BF16 异常值；未来工作才计划扩展到 INT2；
- **依赖离线预处理**：需在部署前完成 Tile-COO 编码和重排序，无法在线动态适应权重变化；
- **小 batch 效率下降**：最小 batch 为 8，低于 8 时引入冗余计算，对真实场景中 batch size = 1 的流式解码不利；
- **额外 warp 分配的性能收益依赖具体场景**：增加稀疏路径 warp 可能减少稠密路径可用 warp，在异常值极少的场景中可能造成资源浪费（论文未评估该 trade-off）；
- **只考虑权重异常值**：未涉及激活异常值（activation outlier）的处理（MixQ 等处理的是激活异常值，属于不同问题范畴）。

### 潜在偏差风险

- 异常值密度（1%–3%）与阈值设定（5%–20%）可能偏向展示方法优势；
- 消费级 GPU 上的结果未必完全代表数据中心级 GPU（如 A100/H100）上的表现，因后者拥有不同的内存带宽与 Tensor Core 规格。

## 总体评价

FlashQuant 提出了一种针对异常值感知量化推理的有效优化方案。其核心洞察虽简洁（消除冗余访存），但通过配套的 Tile-COO 格式、稀疏-稠密分块和重排序策略，将这一洞察落地为可实用的高性能内核。实验证明其在多代 GPU 上的一致性优势，尤其在新架构上表现更佳。该方法与 Marlin 等优化内核正交，有望与后续量化算子优化（如 INT2、激活量化等）叠加，是一个有较高实用价值的研究工作。
